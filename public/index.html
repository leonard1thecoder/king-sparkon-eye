01 / The workflow

One event. One scoped search. One human decision.

The QR-free path starts with an authorized event context. The vision service finds a possible attendee; the ticket system and gate worker retain control of entry.

01 — CONTEXT

Set the event boundary

An authorized worker selects the event or gate context before identification begins.

02 — CAPTURE

Capture at the gate

The browser handles camera interaction and sends the capture with its scoped session reference.

03 — IDENTIFY

Return a candidate

Rust performs vision processing and returns a typed result for the authorized event's gallery.

04 — APPROVE

Keep the decision human

Spring Boot rechecks ticket and worker authority. Entry changes only after explicit approval.

02 / Responsibility

Every system has a job. No system gets every key.

The architecture separates camera interaction, vision processing, and the authoritative admission decision. That boundary is intentional.

01 / Browser

Next.js Tracker

Owns buyer enrollment and gate-worker interaction: camera capture, presenting results, and collecting the worker's explicit action.

02 / Vision

Rust · Eye

Owns bounded image ingress, validation, face detection and vision results. It does not own ticket eligibility or final admission.

03 / Ticket truth

Spring Boot

Remains authoritative for event and ticket eligibility, worker authorization, persistence, and the final admission state.

NON-NEGOTIABLEA match is not an admission. A worker approves. The ticket system decides.

03 / Current state

Built in the open. No pretend production claims.

This repository contains an active Rust service foundation. The complete QR-free admission journey is still being built across the Eye and Tracker systems.

Implemented in this repository

  • Axum service with liveness and readiness routes.
  • Authenticated, bounded photo-assessment ingress and image normalization.
  • Vendored YuNet face-detection pipeline.
  • Conservative assessment behavior while quality thresholds remain uncalibrated.

Still in development

  • Calibrated photo suitability and production-ready recognition.
  • Durable enrollment persistence and production Kafka delivery.
  • Event-scoped 1:N gate identification and end-to-end Tracker integration.
  • Worker-approved admission through the authoritative ticket backend.

Status reflects repository code and its current documentation. A detector result is not identity verification; no liveness or automatic-admission capability is claimed here.
